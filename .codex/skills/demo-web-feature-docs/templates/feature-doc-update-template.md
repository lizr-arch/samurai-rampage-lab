# demo-web Feature Doc Update Template

本模板不是要求逐字照抄，而是用于保证 `demo-web` 功能文档更新时不漏核心信息。

---

## A. Feature Summary 模板

适用时机：

1. 新增一个明确的玩家可见能力层
2. 改变核心交互语义
3. 需要形成新的阶段基线

建议结构：

1. 标题
   - `# Feature Summary v0.X`
2. 阶段定位
   - 这一阶段主要解决什么体验问题
   - 从上一阶段推进到了什么能力层
3. 当前范围
   - 覆盖哪些 UI / 交互
   - 不覆盖哪些系统
4. 核心新增
   - 现在新增了哪些玩家可见能力
   - 每项分别说明“已完成”“当前意义”
5. 当前交互能力
   - 还能做什么
   - 与旧能力如何兼容
6. 当前边界
   - 明确不做什么
   - 目前仍是什么性质的原型
7. 人工验证建议
   - 用户实际能怎么点、怎么拖、怎么验证
8. 当前结论
   - 一句话概括这阶段已经进入什么状态

---

## B. Changelog 模板

适用时机：

1. 记录一个阶段版本
2. 补充当前版本下的小功能条目

建议结构：

1. 版本号
   - `## v0.X`
2. 阶段定位
3. 本阶段新增
   - 页面结构 / 战场 / 布阵 / DevHarness / 资源表达等
4. 本阶段修正的关键问题
5. 当前边界
6. 相关文档

写法要求：

1. 写“功能变化”，不要写实现 diff
2. 要让人能看懂“这个版本比上个版本多了什么”

---

## C. 专题文档模板

适用时机：

1. 某一类交互开始复杂
2. 同一能力需要稳定记录边界

建议结构：

1. 主题目标
2. 当前支持的操作
3. 当前规则
4. 当前限制
5. 与其它模块的关系
6. 推荐人工验证步骤

---

## D. 最终自检

提交前至少检查：

1. 文档描述是否以当前代码行为为准
2. `README` 是否需要补索引
3. `changelog` 是否能追溯本轮变化
4. `feature summary` 是否仍代表最新阶段
5. 是否把未完成能力误写成已完成
