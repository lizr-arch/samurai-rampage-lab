# BattleField Interactions v0.2

本文档记录 `apps/demo-web` 中央 `BattleField` 当前已经支持的交互行为。

目标：

1. 明确战场里用户可以做什么
2. 明确当前交互反馈应该是什么
3. 防止后续修改时丢失已完成的交互能力

---

## 1. 当前定位

`BattleField` 是正式游戏画面的中央战场区域。

当前职责：

1. 展示蓝红双方单位 marker
2. 支持战场上的单位选择
3. 支持轻量单位反馈
4. 支持战斗测试阶段的手动布阵拖拽
5. 支持局部缩放观察
6. 支持战场单位右键删除

当前不承担：

1. 详细部队信息面板
2. 原始调试文本
3. Raw JSON
4. DevHarness 功能按钮
5. 真实战斗逻辑计算

---

## 2. 当前可用交互

### 2.1 点击战场单位选中

已完成：

1. 点击中央蓝方单位，可以选中该单位
2. 点击中央红方单位，可以选中该单位
3. 当前只维护一个选中单位

当前行为：

1. 新选中单位会替换旧选中单位
2. 选中状态会同步到侧栏
3. 选中状态会同步到 `SelectedUnitChip`

### 2.2 Selection Sync

已完成：

1. 战场单位和左右侧栏使用统一的选中状态
2. 点击战场单位后，对应侧栏项同步高亮
3. 点击侧栏项后，对应战场单位同步高亮

当前含义：

1. 用户可以从战场选单位
2. 用户也可以从侧栏选单位
3. 两条交互路径指向同一份 UI state

### 2.3 SelectedUnitChip

已完成：

1. 选中单位后，在战场左上角显示轻量信息反馈
2. 当前显示内容包含：
   - 部队名
   - `Lv`
   - 职责 / 兵种标签
   - 当前人数 / 最大人数
3. 蓝方使用蓝色主题
4. 红方使用红色主题

当前定位：

1. 这是选中反馈层
2. 不是信息大卡片
3. 不应遮挡主战场中央交战区域

### 2.4 单位高亮反馈

已完成：

1. 被选中的单位 marker 会有明显高亮
2. 高亮包含视觉增强效果
3. 高亮状态应能够被肉眼快速识别

当前要求：

1. 高亮不能弱到“点了像没点”
2. 高亮不能退化成几乎不可见的微弱边框

### 2.5 单位拖拽交互

已完成：

1. 蓝方单位支持拖拽
2. 红方单位支持拖拽
3. 拖动中会显示布阵区域 overlay
4. 拖动中单位会提升层级并有视觉反馈

当前说明：

1. 这属于战斗测试布阵交互
2. 不是正式战斗期的移动逻辑

### 2.6 战场缩放交互

已完成：

1. 鼠标滚轮缩放主战场
2. 缩放中心跟随鼠标位置
3. 缩放后可拖动画面查看局部
4. 双击战场空白区域恢复默认视图
5. 战场右下角显示当前缩放倍率

当前说明：

1. 这是观察层交互
2. 不应打断单位点选
3. 不应打断单位拖拽

### 2.7 右键删除

已完成：

1. 对战场已上场单位点右键可直接删除
2. 删除后同步移除侧栏和小地图

当前定位：

1. 右键删除是当前主删除方式
2. 适合快速试阵和清场

## 3. 当前战场单位交互规则

### 3.1 Hit Target 规则

当前规则：

1. 整层 `battlefield-side` 容器不应吞掉鼠标事件
2. 真正可交互的是 `UnitMarker`
3. 单位 marker 必须能稳定响应：
   - hover
   - click
   - drag

当前约束：

1. 不能让上层空容器盖住下层可交互单位
2. 不能出现鼠标移到单位上却没有 hover 反馈的情况

### 3.2 Hover 规则

当前要求：

1. 鼠标移到可拖动单位上时，应能感知其可交互性
2. 当前主要表现为：
   - `cursor: grab`
   - hover 发光或轻量放大

### 3.3 Click 规则

当前要求：

1. 点击单位应触发选中
2. 点击后应同步更新：
   - 战场高亮
   - 侧栏高亮
   - `SelectedUnitChip`

### 3.4 Drag 规则

当前要求：

1. 可拖单位应能稳定跟随鼠标
2. 松手后应根据合法性决定：
   - 提交新位置
   - 回退原位置

### 3.5 Zoom / Pan 规则

当前要求：

1. 滚轮只作用于中央 `BattleField`
2. 战场空白区域可作为平移起点
3. 从单位 marker 上开始操作时，仍优先进入单位交互

### 3.6 Delete 规则

当前要求：

1. 右键应立即删除单位
2. 删除不需要二次确认
3. 删除后 UI 各层同步刷新

---

## 4. 当前视觉反馈要求

### 4.1 选中反馈

当前要求：

1. 选中态必须明显
2. 至少包含发光、描边或缩放中的一种明显反馈
3. 不能出现“已选中但肉眼看不出来”的情况

### 4.2 拖动反馈

当前要求：

1. 拖动中的单位要提升 `z-index`
2. 拖动中的单位要有拖动状态反馈
3. 可布阵区域要有 overlay 提示
4. 非法区域或非法落点要有错误反馈

### 4.3 信息反馈

当前要求：

1. `SelectedUnitChip` 尺寸必须轻量
2. 不得退化为大卡片
3. 不得在战场中央重新出现详细信息面板

---

## 5. 当前禁止项

`BattleField` 当前禁止回流以下内容：

1. 大矩形信息卡
2. troop card
3. army card
4. unit card
5. 长文本说明
6. 原始调试提示文字
7. JSON
8. Raw Events
9. 表格布局
10. 左右列表式主视觉

---

## 6. 当前适合的测试

当前 `BattleField` 适合做以下验证：

1. 点击单位选中
2. 侧栏与战场高亮同步
3. `SelectedUnitChip` 同步
4. 蓝方拖拽命中是否稳定
5. 红方拖拽命中是否稳定
6. hover / click / drag 命中层是否正确
7. 缩放后单位点选和拖拽是否仍正确
8. 右键删除是否稳定

---

## 7. 当前边界

当前 `BattleField` 仍然是：

1. UI 交互测试层
2. mock 数据驱动
3. 非真实战斗状态

当前还不是：

1. battle-core 事件驱动战场
2. 真实移动与碰撞战场
3. 真实技能释放战场
