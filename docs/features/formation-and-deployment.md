# Formation and Deployment v0.3

本文档记录 `apps/demo-web` 当前与阵型、布阵、拖拽摆位相关的功能。

目标：

1. 明确当前阵型功能已经做到哪里
2. 明确蓝红双方拖拽布阵的规则
3. 为后续战斗测试、开战前部署、真实战斗接入提供基线

---

## 1. 当前定位

当前阵型与布阵能力属于：

1. UI 交互测试能力
2. 战斗前摆位能力
3. 开发测试用的轻量部署系统
4. 双侧兵种自由部署沙盘

当前不属于：

1. 真实战斗部署系统
2. 后端保存的正式阵型系统
3. battle-core 驱动的开战前准备流程

---

## 2. 当前已完成能力

### 2.1 Formation Presets

已完成：

1. 底部 `阵形` 按钮可点击
2. 点击后可循环切换蓝方预设阵型
3. 当前预设阵型包括：
   - `arrow` / 锋矢阵
   - `crane` / 鹤翼阵
   - `scale` / 鱼鳞阵

当前行为：

1. 点击 `阵形` 按钮时，蓝方单位位置立刻切换
2. 左侧 ArmyPanel 文本数据不变
3. 红方默认不跟随该按钮切换

### 2.2 Manual Deployment

已完成：

1. 蓝方单位可手动拖拽布阵
2. 红方单位可手动拖拽布阵
3. 拖拽成功后单位会停在新位置
4. 松手非法时回退原位置

### 2.3 Staging Tray Deployment

已完成：

1. 蓝方从左托盘拖兵上场
2. 红方从右托盘拖兵上场
3. 当前可上场兵种包括：
   - 足轻
   - 枪兵
   - 弓兵
   - 铁炮
   - 骑兵
   - 忍者
4. 同一种兵允许重复上场
5. 每边上场上限为 8 队
6. 托盘显示当前军备消耗和剩余额度
7. 托盘兵种卡显示各自出阵 cost

### 2.4 Delete From Battlefield

已完成：

1. 已上场单位支持右键删除
2. 删除后立即释放上场名额

### 2.5 Formation State Label

已完成：

1. 当前阵型状态会在底部标签显示
2. 点击预设阵型后，标签显示预设状态
3. 手动拖拽后，标签切到手动布阵状态

当前示例：

1. `锋矢阵 · 预设阵型`
2. `锋矢阵 · 手动布阵`

当前含义：

1. 阵型来源是预设还是手调可区分
2. 更适合开发测试时判断当前布局状态

## 3. 蓝方部署规则

### 3.1 蓝方可拖动

已完成：

1. 蓝方战场单位可以拖动
2. 拖动后保持选中同步
3. 蓝方拖动成功后会写回当前 UI 状态
4. 蓝方可从左托盘新增单位

### 3.2 蓝方区域限制

当前规则：

1. 蓝方单位只能放在 `BattleField` 左半区
2. 不允许拖到右半区
3. 不允许拖出战场边界

### 3.3 蓝方预设关系

当前规则：

1. 点击 `阵形` 时，蓝方优先应用预设
2. 预设后仍允许继续手动拖动微调
3. 一旦手动拖动，当前状态记为 `手动布阵`
4. 当前蓝方不是固定 5 支队伍，可基于当前已上场队伍重排

## 4. 红方部署规则

### 4.1 红方可拖动

已完成：

1. 红方战场单位可以拖动
2. 红方拖动后保持选中同步
3. 红方拖动成功后会写回当前 UI 状态
4. 红方可从右托盘新增单位

### 4.2 红方区域限制

当前规则：

1. 红方单位只能放在 `BattleField` 右半区
2. 不允许拖到左半区
3. 不允许拖出战场边界

### 4.3 红方与预设关系

当前规则：

1. 当前 `阵形` 按钮主要作用于蓝方预设
2. 红方没有单独的预设阵型切换按钮
3. 红方仍可通过托盘和手动拖拽进行测试摆位

## 5. 合法性规则

### 5.1 边界限制

当前规则：

1. 单位不得拖出 `BattleField`
2. 蓝方不得越过中线到右侧
3. 红方不得越过中线到左侧

### 5.2 最小距离限制

当前规则：

1. 同侧单位之间存在最小距离要求
2. 若释放点距离同侧其他单位过近，则释放失败
3. 失败后回退到拖动前位置

当前说明：

1. 这是轻量规则
2. 当前不做复杂碰撞
3. 当前不做自动避让

### 5.3 非法释放回退

当前规则：

1. 释放在非法半区时回退
2. 释放在边界外时回退
3. 释放在过近位置时回退

### 5.4 上场数量限制

当前规则：

1. 每边最多上场 8 队
2. 超过上限时托盘不应继续成功投放

### 5.6 军备值限制

当前规则：

1. 每边除上场队数外，还受军备预算限制
2. 不同兵种具有不同出阵 cost
3. 骑兵、高机动和高支援单位 cost 更高
4. 当剩余军备不足时，对应兵种不可继续上场
5. 删除已上场单位后，对应军备会返还

当前意义：

1. 战斗准备开始具备构筑取舍
2. 当前阵容不再是无限补兵的纯沙盘
3. 玩家需要在高 cost 强单位和低 cost 基础单位之间做选择

### 5.5 删除规则

当前规则：

1. 右键已上场单位可直接删除
2. 删除后战场、侧栏、小地图同步移除

## 8. Deployment Mode 关系

v0.3 起，阵型与布阵不再只影响战场画面，也会影响 `DevHarness` 对 Run 结果有效性的判断。

### 8.1 当前战场输入

当前战场输入由以下内容共同决定：

1. 当前 Scenario Preset
2. 当前双方已上场单位
3. 当前双方单位位置
4. 当前 `Seed`
5. 当前 Run 规模语义：`1v1` 或 `5v5`

`DevHarness` 会把输入来源显示为：

1. 默认模板
2. Scenario Preset 模板
3. 模板后已手调
4. 随机重排后的当前阵容

### 8.2 会让旧 Run 结果过期的操作

如果已经执行过 Run，以下操作会把旧 `Raw Events / Test Result` 标为过期：

1. 拖兵上场
2. 拖动已上场单位
3. 右键删除单位
4. 点击蓝方 `阵形`
5. 点击 `Random Formation`
6. 点击 `Scenario Preset`
7. 修改 `Seed`

当前规则：

1. 旧结果内容保留
2. 结果标题显示 `已过期，请重新 Run`
3. 不自动刷新 Run 结果

### 8.3 不会让旧 Run 结果过期的操作

以下操作不改变当前战场输入：

1. 修改 `Speed`
2. `Export Replay`
3. `Import Replay`
4. `Validate Content`
5. 播放控制按钮

当前规则：

1. `Speed` 只影响播放 / 显示
2. 数据工具只更新 `工具状态`
3. 数据工具不覆盖 `Raw Events / Test Result`

### 8.4 Run 规模语义

点击 `Run 1v1 / Run 5v5` 时：

1. 使用当前上场单位和当前位置
2. 不重新套 Scenario Preset
3. 不覆盖当前阵型
4. 会把当前 troop 数值重算到所选规模
5. 重算保留单位 id、archetype 和位置

这意味着：

1. 用户可以先摆阵，再选择用 `1v1` 或 `5v5` 规模运行
2. Run 规模会影响 ArmyPanel 中 troop 数值语义
3. Run 结果状态会切到 `对应当前战场`
