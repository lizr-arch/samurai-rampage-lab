# Feature Summary v0.3

本文档用于记录 `apps/demo-web` 在 `v0.3` 阶段新增后的功能基线。

本阶段重点是补齐 `DevHarness` 的部署状态语义，让“当前战场输入”和“Run 结果有效性”可以被用户直接读懂。

同时，本阶段也开始把“战斗准备”从纯摆位推进到带约束的出阵玩法。

---

## 1. 当前范围

当前总结范围覆盖：

1. `DevHarness` 部署状态块
2. `Run 1v1 / Run 5v5` 结果有效性
3. `Scenario Preset / Seed / Random Formation / Reset Battle` 的状态迁移
4. `Export Replay / Import Replay / Validate Content` 的工具状态
5. 当前布阵按 1v1 / 5v5 规模重算 troop 数值
6. 战斗准备阶段的军备值和兵种 cost 约束

当前不覆盖：

1. `packages/battle-core`
2. `packages/battle-rules`
3. 真实战斗结算
4. 历史 Run 结果对比
5. 撤销 / 重做

---

## 2. v0.3 核心新增

### 2.1 Deployment Mode 状态块

已完成：

1. `DevHarness` 顶部新增 `部署状态`
2. 状态块显示主状态
3. 状态块显示当前输入说明
4. 状态块显示 Run 结果有效性

主状态包括：

1. `当前可运行`
2. `已运行：1v1`
3. `已运行：5v5`
4. `结果已过期，请重新 Run`

当前输入说明包括：

1. 默认模板
2. 当前 Scenario Preset 模板
3. 模板后手调
4. 随机重排后的当前阵容

### 2.2 Run 结果有效性

已完成：

1. `Raw Events` 只展示 Run 结果
2. `Test Result` 只展示 Run 结果
3. 用户改动战场后旧结果内容保留
4. 旧结果标题会明确标记为已过期

结果标题包括：

1. `Raw Events · 未运行`
2. `Raw Events · 对应当前战场`
3. `Raw Events · 已过期，请重新 Run`
4. `Test Result · 未运行`
5. `Test Result · 对应当前战场`
6. `Test Result · 已过期，请重新 Run`

当前含义：

1. 内容是否存在和内容是否有效被分开表达
2. 用户可以继续查看旧结果
3. 用户也能明确知道旧结果不再对应当前战场

### 2.3 输入变更不再自动 Run

已完成：

1. 点击 `Scenario Preset` 只覆盖部署模板
2. 修改 `Seed` 只改变后续随机和下次 Run 的输入
3. 拖动、部署、删除、阵型、随机重排都会把已运行结果标为过期
4. 修改 `Speed` 只影响播放 / 显示，不影响结果有效性

当前规则：

1. 如果尚未 Run，输入变更后仍保持 `未运行`
2. 如果已经 Run，输入变更后进入 `已过期`
3. 不会因为改 preset 或 seed 自动刷新 Raw Events / Test Result

### 2.4 Run 按当前战场切换规模

已完成：

1. `Run 1v1` 会把当前上场单位重算为 1v1 troop 数值
2. `Run 5v5` 会把当前上场单位重算为 5v5 troop 数值
3. 重算时保留单位 side、id、archetype 和当前位置
4. Run 不覆盖当前阵型
5. Run 不重新套 Scenario Preset

当前含义：

1. 规模是 Run 输入的一部分
2. 布阵是用户当前战场输入
3. Run 只更新结果有效性和 troop 规模语义

### 2.5 工具状态独立

已完成：

1. `DevHarness` 数据工具区新增 `工具状态`
2. `Export Replay` 只更新工具状态和战场提示
3. `Import Replay` 只更新工具状态和战场提示
4. `Validate Content` 只更新工具状态和战场提示
5. 工具按钮不再覆盖 `Raw Events / Test Result`

当前含义：

1. Run 结果区不再被工具输出污染
2. 工具反馈仍然可见
3. Run 结果有效性只由 Run 和战场输入决定

### 2.6 战斗准备军备值

已完成：

1. 托盘顶部显示当前军备消耗和剩余额度
2. 每个兵种卡显示出阵 cost
3. 当前阵容不再只受 `8 队上限` 约束
4. 当前阵容还会受军备预算约束
5. 预算不足时，对应兵种卡会禁用
6. 删除已上场单位后，军备值会立即回退

当前规则：

1. `1v1` 使用较紧的默认军备预算
2. `5v5` 使用更高的默认军备预算
3. 骑兵和高机动 / 高支援单位 cost 更高
4. 托盘禁用状态会随当前阵容实时变化

当前含义：

1. 战斗准备不再只是无限拖兵摆位
2. 玩家开始需要在兵种强度和出阵数量之间做取舍
3. `demo-web` 开始具备最基础的构筑约束

## 3. 当前交互能力

### 3.1 Reset Battle

当前行为：

1. 恢复默认模板
2. 恢复 `1v1`
3. 清空上次 Run 绑定
4. Run 结果状态回到 `未运行`
5. `Raw Events / Test Result` 回到未运行文案

### 3.2 Scenario Preset

当前行为：

1. 立即覆盖双方站位模板
2. 蓝方阵型标签回到 `锋矢阵 · 预设阵型`
3. 清空选中单位
4. 保留当前 1v1 / 5v5 规模
5. 不自动 Run

### 3.3 Seed

当前行为：

1. 修改 Seed 会影响后续 `Random Formation`
2. 修改 Seed 会影响下次 Run 输出
3. 如果旧结果已经存在，旧结果会被标为过期
4. 不自动刷新 Run 结果

### 3.4 Random Formation

当前行为：

1. 只打乱当前已上场单位的位置
2. 不改变兵种构成
3. 不改变当前 Scenario Preset 选择
4. 如果旧结果已经存在，旧结果会被标为过期

### 3.5 Battle Prep

当前行为：

1. 托盘显示 `军备 已用/总量 · 剩余`
2. 每张兵种卡显示 cost 点数
3. 当达到上限或军备不足时，对应卡片不可继续拖入
4. 删除已上场单位后，相关 cost 会退回
5. `Run 1v1 / Run 5v5` 切换后，军备上限会跟随规模同步变化

## 4. 当前边界

当前已明确不做：

1. 真实 battle-core 运行
2. 真实 replay 导入导出
3. 历史 Run 结果列表
4. 结果差异对比
5. 二次确认弹窗
6. `GameFrame` 内持久 Deployment HUD
7. 正式的队伍编制槽 / 前后排槽位规则
8. 兵种重复限制

当前仍属于：

1. mock 驱动的开发沙盘
2. UI / 交互 / 状态语义验证层
3. 后续接真实战斗前的运行输入基线

---

## 5. 人工验证建议

1. 初始进入页面，确认状态块显示 `当前可运行`，结果区显示未运行
2. 点击 `Run 1v1`，确认状态块显示 `已运行：1v1`，结果标题显示 `对应当前战场`
3. 跑完后拖动任意单位，确认旧结果内容保留，但标题变为 `已过期，请重新 Run`
4. 跑完后修改 `Seed`，确认不会自动刷新 Raw Events / Test Result
5. 点击 `Scenario Preset`，确认站位覆盖但不会自动 Run
6. 点击 `Export Replay / Import Replay / Validate Content`，确认只更新工具状态
7. 点击 `Run 5v5`，确认当前阵型不被重置，ArmyPanel troop 数值切到 5v5 规模
8. 点击 `Reset Battle`，确认恢复默认模板、`1v1`、未运行态
9. 连续补高 cost 单位，确认预算不足的托盘卡会禁用
10. 删除已上场单位，确认托盘预算和可部署状态会恢复

---

## 6. 当前结论

截至 `v0.3`，`demo-web` 的开发沙盘已经可以清楚区分：

1. 当前战场输入是什么
2. 屏幕上的 Run 结果是否仍然对应当前战场
3. 哪些操作会改输入
4. 哪些操作只改工具反馈或显示参数
5. 当前阵容在开战前是否仍有出阵空间

这份文档应作为后续接真实 battle-core、正式 replay 或部署锁定模式前的 DevHarness 状态语义基线。
