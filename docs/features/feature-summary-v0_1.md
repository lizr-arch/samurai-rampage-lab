# Feature Summary v0.1

本文档用于记录 `apps/demo-web` 当前已经完成的 UI 功能基线。

目标不是记录实现细节，而是回答 3 个问题：

1. 当前已经具备哪些功能
2. 用户可以如何操作这些功能
3. 当前边界和限制是什么

---

## 1. 当前范围

当前总结范围仅覆盖 `demo-web` 的 UI 垂直切片，包括：

1. 正式 `game-frame`
2. `BattleField`
3. ArmyPanel 侧栏
4. TopHud
5. BottomCommandBar
6. DevHarness
7. 与战斗测试相关的轻量交互

当前不覆盖：

1. `packages/battle-core`
2. `packages/battle-rules`
3. `packages/contracts`
4. `packages/content`
5. `packages/replay`
6. 真实战斗逻辑

---

## 2. 已完成功能总览

### 2.1 Game Frame 基础结构

已完成：

1. 页面上方为固定逻辑尺寸 `1920×1080` 的正式游戏画面
2. 浏览器窗口变化时，`game-frame` 会等比缩放并居中
3. 页面下方存在独立的 `DevHarness`
4. `DevHarness` 不参与 `1920×1080` 缩放
5. 页面整体可纵向滚动

当前含义：

1. 上方区域是正式玩家可见 UI
2. 下方区域是开发测试区
3. 两者已在结构上分离

### 2.2 TopHud

已完成：

1. 蓝方分数显示
2. 红方分数显示
3. 蓝方主将名显示
4. 红方主将名显示
5. 中央战斗时间显示
6. 蓝红双方士气/兵力条显示
7. 像素风 HUD 边框和深色战国风外观

### 2.3 左右 ArmyPanel

已完成：

1. 左侧蓝方侧栏
2. 右侧红方侧栏
3. 主将头像占位
4. 部队列表显示
5. 每个部队项显示：
   - 名称
   - `Lv`
   - 当前人数 / 最大人数
   - HP 条
   - 职责标签

当前定位：

1. ArmyPanel 是状态栏
2. 详细部队信息留在侧栏
3. 中央 `BattleField` 不承担详细信息面板职责

### 2.4 BattleField 主视觉

已完成：

1. 中央战场背景图接入
2. 背景图作为正式战场底图使用
3. 单位以战场 marker 形式显示
4. 蓝方单位从左侧布阵
5. 红方单位从右侧布阵
6. 保留伤害数字、攻击轨迹、冲突中心和“激突”标题
7. 中央区域不再使用大信息卡作为主视觉

当前定位：

1. `BattleField` 是实时战场视觉区域
2. 主视觉应该是双方交战空间
3. 不是战术列表，不是后台面板

### 2.5 UnitSquad / UnitMarker

已完成：

1. 蓝方与红方单位 marker 分色
2. 近战与远程样式区分
3. 使用透明 sprite 作为兵团视觉资源
4. 单位上方保留轻量血条
5. 单位保留等级标记
6. 单位支持选中态高亮

当前定位：

1. 单位 marker 用于战场交互
2. 单位 marker 不是详细信息卡
3. 详细说明不应回流到中央战场

### 2.6 BottomCommandBar

已完成：

1. 小地图区域占位
2. 暂停按钮
3. 播放按钮
4. 快进按钮
5. 倍速显示
6. 战术按钮：
   - 阵形
   - 鼓舞
   - 前进
   - 退却
   - 奇袭
   - 要请
7. 阵型标签显示位

### 2.7 DevHarness

已完成：

1. `Run 1v1`
2. `Run 5v5`
3. `Reset Battle`
4. `Random Formation`
5. Seed 输入
6. 速度切换
7. `Export Replay`
8. `Import Replay`
9. `Validate Content`
10. `Raw Events` 显示区
11. `Test Result` 显示区

当前定位：

1. `DevHarness` 属于开发测试区
2. 不属于正式玩家 UI
3. 不应放回 `game-frame` 内

## 3. 当前交互功能

### 3.1 Selection Sync

已完成：

1. 点击左侧蓝方部队列表项，可选中对应蓝方单位
2. 点击右侧红方部队列表项，可选中对应红方单位
3. 点击中央蓝方单位，可同步高亮左侧对应部队
4. 点击中央红方单位，可同步高亮右侧对应部队
5. 同一时间只维护一个 `selectedUnitId`

当前效果：

1. 侧栏和战场高亮同步
2. 用户可以从侧栏选单位
3. 用户也可以直接从战场选单位

### 3.2 SelectedUnitChip

已完成：

1. 选中单位后，在 `BattleField` 左上显示轻量信息反馈
2. 显示内容包含：
   - 部队名
   - `Lv`
   - 职责 / 兵种标签
   - 当前人数 / 最大人数
3. 蓝方选中显示蓝色主题
4. 红方选中显示红色主题
5. 无选中时可隐藏

当前定位：

1. 这是轻量反馈层
2. 不是大面板
3. 不应遮挡主战场

### 3.3 Formation Presets

已完成：

1. 点击底部 `阵形` 按钮可循环切换蓝方预设阵型
2. 当前预设包括：
   - `arrow` / 锋矢阵
   - `crane` / 鹤翼阵
   - `scale` / 鱼鳞阵
3. 切换时蓝方位置变化
4. 红方位置默认不受该按钮影响
5. 当前阵型名会显示在底部标签区域

当前约束：

1. 阵型预设当前主要服务蓝方测试
2. 红方尚未定义单独预设阵型切换逻辑

### 3.4 Manual Formation Drag

已完成：

1. 蓝方单位支持拖拽布阵
2. 红方单位支持拖拽布阵
3. 蓝方只能放在左半区
4. 红方只能放在右半区
5. 不允许拖出 `BattleField`
6. 非法释放会回到拖动前位置
7. 拖动中有可布阵区域提示
8. 拖动中单位有提升层级和视觉反馈

当前规则：

1. 蓝方属于左半区布阵测试
2. 红方属于右半区布阵测试
3. 双方拖拽主要用于战斗前测试摆位

### 3.5 最小防重叠

已完成：

1. 同阵营单位释放时会进行最小距离检查
2. 如果距离同侧其他单位过近，则释放失败并回退

当前说明：

1. 这是轻量规则
2. 不是完整碰撞系统
3. 当前仅用于避免明显重叠

### 3.6 阵型状态标签

已完成：

1. 点击 `阵形` 按钮后，标签显示当前预设阵型
2. 当用户继续手动拖动单位后，标签会切换到手动布阵状态

当前示例：

1. `锋矢阵 · 预设阵型`
2. `锋矢阵 · 手动布阵`

当前意义：

1. 预设阵型和手调阵型能够区分
2. 更适合后续战斗测试和开发调试

## 4. 当前功能边界

### 4.1 已明确不做的内容

当前未实现：

1. 真实战斗推进
2. 真实攻击判定
3. 真实单位移动逻辑
4. 真实伤害结算
5. 真实事件流驱动
6. 后端存储
7. 多选单位
8. 网格吸附
9. 复杂碰撞
10. 红蓝双方 AI 行为

### 4.2 当前系统边界

当前 UI 仍属于：

1. HTML / CSS / TypeScript DOM UI
2. mock 数据驱动
3. 测试导向的交互原型

当前 UI 还不属于：

1. battle-core 驱动的真实战斗前端
2. PixiJS 渲染战场
3. 实时事件回放系统

---

## 5. 当前适合的测试用途

当前这套 UI 最适合做以下测试：

1. `game-frame` 正式 UI 框架验证
2. `BattleField` 主视觉验证
3. 单位选中同步验证
4. 战场单位拖拽布阵验证
5. 蓝红双方左右半区布阵限制验证
6. 阵型预设切换验证
7. `DevHarness` 场景切换验证
8. 未来真实战斗接入前的交互预演

---

## 6. 人工验证建议

### 6.1 结构验证

1. 打开页面，确认上方为完整 `1920×1080` 正式游戏画面
2. 缩放浏览器窗口，确认 `game-frame` 等比缩放
3. 向下滚动，确认 `DevHarness` 在 `game-frame` 下方

### 6.2 选择验证

1. 点击左侧部队，确认中央对应单位高亮
2. 点击右侧部队，确认中央对应单位高亮
3. 点击中央蓝方单位，确认左侧高亮同步
4. 点击中央红方单位，确认右侧高亮同步
5. 确认 `SelectedUnitChip` 内容随选中单位变化

### 6.3 阵型验证

1. 点击底部 `阵形`
2. 确认蓝方切换到不同预设位置
3. 确认标签显示 `预设阵型`

### 6.4 拖拽验证

1. 拖动蓝方单位，确认只能停在左半区
2. 拖动红方单位，确认只能停在右半区
3. 将单位拖到非法区域，确认会回退
4. 将单位拖到过近位置，确认会回退
5. 拖动成功后，确认标签显示 `手动布阵`

## 7. 后续建议演进

建议按以下顺序继续推进：

1. 静态 UI 基线稳定
2. mock events 驱动 UI 局部变化
3. 明确 BattleEvent 合同
4. battle-core v0.1 接入
5. UI 接真实事件流
6. 区分开发布阵模式与正式战斗模式

---

## 8. 当前结论

截至 `v0.1`，`demo-web` 已经不只是静态页面，而是具备以下测试价值的 UI 切片：

1. 可选中
2. 可高亮同步
3. 可预设阵型
4. 可手动拖拽布阵
5. 可区分正式游戏画面与开发测试区

这份文档应在每次新增交互能力后持续更新，作为 `demo-web` 的功能基线记录。
