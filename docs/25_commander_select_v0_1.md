# 25 Commander Select v0.1

## 1. 目标

让玩家可以在两个主帅之间切换，并让正式 UI 显示当前主帅。
切换主帅后，底部军令 / 军旗入口随当前主帅变化。

本阶段是 UI / 交互原型，不实现真实战斗、数值加成和复杂军令效果。

## 2. 两个主帅

### 2.1 破阵主帅

- id: `charge_commander`
- name: 破阵主帅
- title: 冲阵型
- styleTags: 进攻 / 冲锋 / 快节奏
- maxBanners: 3
- initialBanners: 3
- description: 擅长推动全军压上，并通过冲锋旗制造局部突破。
- commandItems:
  - 全军前进（点击型军令）
  - 冲锋旗（投放型军旗）

### 2.2 筹策主帅

- id: `strategy_commander`
- name: 筹策主帅
- title: 调度型
- styleTags: 休整 / 集结 / 稳阵
- maxBanners: 3
- initialBanners: 3
- description: 擅长稳住阵线，并通过集结旗调度局部部队。
- commandItems:
  - 停下休整（点击型军令）
  - 集结旗（投放型军旗）

## 3. 主帅和军令 / 军旗的关系

每个主帅拥有两类指令：

1. **点击型军令（clickOrder）** — 点击即生效，不消耗令旗，无 CD
2. **投放型军旗（placeBanner）** — 点击进入投放模式，在战场点击落旗，消耗令旗，有 CD

切换主帅后：
- 底部按钮随当前主帅变化
- 令旗重置为该主帅的 initialBanners
- 清除武装状态和 CD

## 4. 为什么第一版只做两个主帅

- 两个主帅形成鲜明对比：进攻 vs 防守，冲击 vs 稳固
- 保持数据量小，方便迭代
- 后续在更复杂的指令系统中再引入第三个主帅

## 5. 本阶段不做

- 不实现真实战斗
- 不实现主帅数值加成
- 不实现主帅升级
- 不实现主帅技能树
- 不实现右键命令 / 框选 / 画线
- 不修改 packages/*

## 6. 后续计划

### 点击型军令

- 全军前进：所有己方部队向敌方阵地移动
- 停下休整：所有己方部队停止移动，原地防守

### 投放型军旗

- 冲锋旗：范围内己方部队进入冲锋倾向
- 集结旗：范围内己方部队进入集结倾向

### 令旗恢复

- 随时间自动恢复
- DevHarness 提供"恢复令旗"按钮

### 军令状态反馈

- 有效范围内部队头顶显示命令状态标签
- 新命令覆盖旧命令
- 到期自动消失
